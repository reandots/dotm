# chezmoi, фильтрация и инвентаризация файлов

[Документация](README.md) · [English](../en/chezmoi.md)

## Владение и требования

В `[configurations.configs]` выбранного набора указываются `backend = "chezmoi"` и Git `repository`. dotm использует общую рабочую копию `${XDG_DATA_HOME:-$HOME/.local/share}/chezmoi`, обычные настройки/кеш/постоянное состояние chezmoi и его действующий каталог назначения. Второго приватного окружения chezmoi нет. Git и chezmoi должны быть доступны заранее; chezmoi v2.74.1 — проверенная версия, а не доказанный минимум.

Поддерживается только обычный `mode = "file"`. Объявленные пути должны отображаться внутрь действующего `destDir`. Раскрытие `$XDG_CONFIG_HOME` в декларации **не переносит** исходный `dot_config`: он отображается по правилам структуры chezmoi. Не расширяйте назначение до `/` ради обхода ограничения; обеспечьте совместимые исходники/настройки.

## Явное подключение внешней политики

Интеграция обязательна перед применением конфигурационных целей dotm. Закрепите её в автоматизации dotfiles/хоста, а не оставляйте недокументированной ручной предпосылкой.

1. В настоящем репозитории dotfiles добавьте включение из [examples/chezmoi-policy/.chezmoiignore](../../examples/chezmoi-policy/.chezmoiignore) в `.chezmoiignore` действующего корня исходников. При `.chezmoiroot` это выбранный им корень. Сохраните существующие корневые и вложенные нативные правила; не заменяйте их сгенерированным разрешающим списком.
2. Обычные статические настройки chezmoi должны выбирать общий источник, правильное назначение и `mode = "file"`. Сохраните прочие настройки/данные.
3. Запустите `./dotm files lint`, чтобы узнать вычисленный **Policy path**. Ошибки первого запуска об отсутствии политики/интеграции ожидаемы, но это не успешная проверка.
4. В обычной конфигурации chezmoi (как правило, `${XDG_CONFIG_HOME:-$HOME/.config}/chezmoi/chezmoi.toml`) привяжите выведенный абсолютный путь:

   ```toml
   [data.dotm]
   policyFile = "/absolute/path/reported/by/files-lint.json"
   ```

   Замените пример настоящим путём. Имя зависит от действующих путей файла настроек, корня исходников и назначения; не копируйте хеш другой машины. После изменения привязки нужен новый путь.
5. Закоммитьте/опубликуйте изменения исходников и оставьте рабочую копию чистой перед синхронизацией. Выполните `./dotm files refresh` для локальной проверки/публикации, затем `./dotm files lint` для проверки обычной интеграции. Если источник ещё не получен, после настройки источника/интеграции используйте `./dotm files refresh --update-source`.

Сгенерированный JSON находится вне Git: `${XDG_STATE_HOME:-$HOME/.local/state}/dotm/files/chezmoi/<key>.json`. Не пишите его вручную. Шаблон привязывает политику к URL Git origin, действующим путям источника/назначения/конфига и схеме. Он читает буквальные строки JSON, а не вычисляет сгенерированный шаблонный код. Отдельный ID репозитория не нужен.

Без опубликованной политики самостоятельный chezmoi сохраняет нативное поведение. С политикой он использует **последний опубликованный выбор**, а не автоматически текущий выбор dotm. Изменения выбора/деклараций/исходников/настроек могут сделать политику устаревшей: обновите её. Обычные add/edit для исключённых путей могут отказать или проигнорировать ввод; исключения — не универсальная песочница и не запрет добавления посторонних файлов.

## Получение и смена источника

Install/update/update cfg получают или fast-forward-обновляют источник перед применением готовых целей. Отсутствующий источник подготавливается и проверяется до активации. Существующий должен быть чистой самостоятельной непустой Git-копией на ветке с одним upstream в origin и безопасной структурой. Изменения tracked/index/untracked/ignored, включая пустые неотслеживаемые каталоги, блокируют синхронизацию. Detached, ahead/diverged, shallow, linked/shared/sparse/submodule-копии и скрывающие изменения index-флаги отклоняются. Автоматических stash, reset, clean, rebase и ремонта нет.

Другой репозиторий требует отдельного подтверждения. Только полная строка строчного **`yes` с переводом строки** разрешает замену; другой ответ, EOF или незавершённая строка — отказ. `--yes` удаления/очистки не относится к этому вопросу. До вопроса dotm доказывает публикацию всех старых локальных объектов в объявленной истории origin, консервативно включая ветки, reflog и dangling-объекты. Недоступность доказательства блокирует замену. URL-сравнение не угадывает эквивалентность SSH/HTTPS.

Старая копия сохраняется по выведенному backup-пути, автоматически не удаляется. Файлы назначения при смене источника/набора не удаляются. Прерывание передачи требует осознанного восстановления: см. [устранение проблем](troubleshooting.md).

## Проверка и применение

```sh
./dotm cfg lint
./dotm cfg lint --source /absolute/local/checkout
./dotm update cfg
```

`cfg lint` пассивно проверяет **весь** локальный действующий источник/настройки, включая невыбранные приложения и нативные ignores. Ничего не загружает, не вычисляет шаблоны, не выполняет код и не пишет состояние. Манифесты и бинарный файл chezmoi не нужны. Запрещены run/modify/remove/exact-действия, автоматические externals, настроенные хуки и Git autoAdd/autoCommit/autoPush, конфликтующий sourceDir, `mode=symlink`, динамические шаблоны конфигурации и ссылки на каталоги исходников. Обычные доверенные файловые шаблоны/partials и описания целевых ссылок `symlink_` — другой случай и могут поддерживаться. Проверяется синтаксис статической конфигурации/данных. Это консервативные ограничения dotm, не общие ограничения chezmoi.

Успешная пассивная проверка не доказывает корректность шаблонов или успешность apply. Действующие файловые проверки/применение вычисляют доверенные шаблоны, чьи helpers могут выполнять команды. Настройки Git, transport/filter helpers и credentials тоже доверенные.

Готовность конфигурации требует полного набора пакетов приложения/зависимостей; беспакетному приложению историческая отметка установки не нужна. `update cfg` пропускает приложения с недостающими пакетами, а не устанавливает их. Хуки готовых конфигураций повторяются даже без изменений. Пустой набор целей не превращается в неограниченный apply.

Применение идёт по выбранным управляемым записям с нативной защитой конфликтов: без принудительной перезаписи/merge и широкой очистки. Несовместимые типы и символьные ссылки в предках — конфликты. Локальные изменения, различия при первом принятии и различия прав сохраняются; безопасные независимые файлы уже могли измениться. Нативные ignores действуют. Конфликты блокируют post-хуки приложения/потребителей, а не всю независимую работу. Отката назначения/хуков нет.

## Команды политики файлов

```sh
./dotm files lint
./dotm files refresh
./dotm files refresh --update-source
./dotm files status
```

Все используют желаемое замыкание зависимостей независимо от готовности пакетов и необязательный [локальный files.toml](configuration.md). Исключения охватывают configs невыбранных приложений, unmanaged выбранных и локально признанные данные. Это буквальные корни/поддеревья, включая будущих потомков, а не общий разрешающий список.

`lint` проверяет декларации, действующие нативные правила, свежесть/привязку политики и реальную интеграцию без постоянной публикации. Нативные `!`-правила, пересекающие сгенерированные исключения, дают ошибку даже для отсутствующих путей; полностью скрытая нативными правилами выбранная конфигурация даёт предупреждение. Предупреждения допускают продолжение, ошибки блокируют применение. Это не пассивный lint: шаблоны вычисляются, возможны временные проверочные файлы.

`refresh` проверяет новый кандидат, не требуя свежести старой политики, затем атомарно заменяет JSON и проверяет обычную интеграцию. Ошибка до публикации сохраняет старую политику; после публикации не откатывает её. `--update-source` явно добавляет получение/загрузку исходников с правилами безопасности/подтверждения. `status` делает тот же локальный refresh без загрузки. Обе команды держат блокировку; незавершённое восстановление пакетов блокирует их без запуска Nix. Читающий lint не восстанавливает состояние.

Install/update/update cfg обновляют эту политику после pre-конфигурационных хуков и получения источника, перед ограниченным apply. Ошибки политики сохраняют уже зафиксированную пакетную часть.

## Интерпретация инвентаризации

`files status` разделяет **локальные изменения**, **ожидающие изменения chezmoi** и **неотслеживаемые файлы**, сохраняя оба направления статуса и владельцев. Пустые разделы опускаются. Терминал использует оформление, если не задан `NO_COLOR`; перенаправленный вывод остаётся обычным текстом с экранированием необычных путей.

Неотслеживаемое означает **неклассифицированное**, а не недавно созданное или безопасное для удаления. Классификация учитывает нативные ignores, unmanaged выбранных приложений и локальные исключения. Исключения других профилей не признают их существующие остатки известными; неизвестные соседи внутри выбранных configs остаются кандидатами. Инвентаризация охватывает HOME и поддерживаемые XDG-корни внутри назначения, считает ссылки листьями и при неполном сборе возвращает ошибку, а не чистый статус. Она не применяет файлы и не запускает хуки приложений, но намеренно меняет постоянную политику фильтрации и вычисляет доверенные шаблоны.
