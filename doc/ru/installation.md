# Установка и первое развёртывание

[Документация](README.md) · [English](../en/installation.md)

## Сборка CLI

В доверенной рабочей копии с установленным Go:

```sh
go build .
./dotm --help
```

Команда создаёт `./dotm`, но не устанавливает его в PATH. Примеры руководства предполагают запуск из рабочей копии. Размещение бинарного файла в пользовательском PATH можно закрепить в своей автоматизации.

Модуль объявляет Go 1.23.0. Сборка и проверки CLI выполнялись с Go 1.27.4 на Linux/amd64; более старые версии не проверены. Для загрузок нужны сеть и доступные для записи кеши Go. Закреплённые инструменты и `just setup` описаны в [разработке](development.md). `dotm init` настраивает уже работающий dotm, но не устанавливает сам исполняемый файл dotm.

## Отдельная подготовка хоста

Пакетные операции требуют уже настроенного **многопользовательского демона Nix**. dotm не устанавливает и не обновляет сам Nix. Home Manager, sudo и права доверенного пользователя не нужны. Nix 2.35.6 — проверенная версия, а не установленный минимум.

От имени пользователя приложений выполните:

```sh
nix --version
nix store info
nix config show experimental-features
nix config show use-xdg-base-directories
```

Ожидаются хранилище daemon, `Trusted: 0`, функции `nix-command` и `flakes`, включённые базовые каталоги XDG. Каталог `${XDG_STATE_HOME:-$HOME/.local/state}/nix` должен быть заранее создан и доступен пользователю для записи. Нестандартные XDG-пути должны быть абсолютными и совпадать при подготовке хоста и в пользовательском сеансе. Для пакетов и исходников также нужны сеть и доступные для записи кеши/состояние Nix.

Автоматизация хоста и сеанса должна подключить:

- `${XDG_STATE_HOME:-$HOME/.local/state}/nix/profile/bin` к `PATH`;
- каталог `share` этого профиля к путям поиска приложений, например `XDG_DATA_DIRS`.

После изменения настроек сеанса начните новый сеанс. dotm не меняет вызывающую оболочку, login shell, службы или графический сеанс. Хуки получают `bin` профиля только в собственном PATH. Проверенная подготовка Arch описана в [БЗ](../../.agent/nix-host.md).

Для работы с конфигурационными файлами нужен Git. `dotm init` может использовать совместимый chezmoi или получить канонический дескриптор nixpkgs `chezmoi` через Nix в стандартный XDG-профиль, не устанавливая выбранные приложения. Проверяются необходимые операции и форматы, а не произвольная минимальная версия; существующий непригодный кандидат нужно исправить, а не молча перекрыть другим. Команда не устанавливает Nix или Git, не настраивает хост/сеанс, оболочку, службы и системные параметры. Полученный бэкенд отдельно записывается в машинный `dotm/infrastructure.json` внутри XDG state, отображается как инфраструктура в `status` и защищён от `remove-extras`, включая `--yes`. Внешние исполняемые файлы не присваиваются dotm; настройка PATH/share для сеанса остаётся отдельной.

## Размещение входных данных

Стандартная структура:

```text
${XDG_CONFIG_HOME:-$HOME/.config}/dotm/
  config.toml              # локальный выбор конфигурации
  files.toml               # необязательные локальные исключения
  data/
    catalog.toml           # общий каталог приложений
    configurations.toml    # общие именованные конфигурации
    hooks/                 # необязательные исполняемые хуки
```

`data/` может быть рабочей копией Git или ссылкой на неё. Обычные команды не создают и не загружают отсутствующие манифесты; `init` может создать отсутствующие входные файлы dotm в рамках одобренной настройки, но не загружает удалённые общие манифесты. `--data-dir` меняет только общие входные файлы, но не локальные настройки; автоматического поиска в текущем каталоге нет. См. [форматы](configuration.md).

Для новой настройки init может подготовить локальный выбор после проверки плана; заранее создавать `config.toml` не обязательно, если передан `--configuration` или значение однозначно определяется существующими данными. Init проверяет/создаёт только файлы dotm, необходимые для одобренной настройки, и не придумывает конфигурацию, если её имя не определено. Например, если в `configurations.toml` объявлен `laptop`, init может подготовить для него локальный выбор. Существующие файлы редактируйте, а не перезаписывайте.

Если вы хотите вручную подготовить локальный выбор, минимальная запись выглядит так:
```toml
configuration = "laptop"
```

Имя должно существовать в вашем `configurations.toml`. Существующий файл редактируйте, а не перезаписывайте. Каталог пакетных примеров выбирается через `--data-dir examples`; безопасный изолированный просмотр описан в [примерах](examples.md).

## Инициализация dotm

После сборки или иной установки исполняемого файла dotm и внешней подготовки Nix/Git выполните `init` для настройки бэкенда файлов и интеграции политики:

```sh
./dotm init --configuration laptop --repository https://example.invalid/user/dotfiles.git
# Для нестандартных общих манифестов (глобальный параметр перед командой):
./dotm --data-dir /path/to/data init --configuration laptop --repository https://example.invalid/user/dotfiles.git
```

`--configuration` задаёт именованную конфигурацию, а `--repository` — источник chezmoi. Опускайте параметр только если существующие локальные данные однозначно задают значение. Глобальный `--data-dir` выбирает общие манифесты и не перемещает локальные настройки машины. Init проверяет доступные входные данные и целевые пути, затем отдельно запрашивает согласие на изменения локальных намерений и, если требуется, замену источника. Обхода через `--yes` нет; отмена или неполный ввод останавливают настройку до соответствующих записей.

Команда создаёт или обновляет одобренные файлы dotm, получает пригодный chezmoi при необходимости, проверяет или получает настроенный checkout, подготавливает совместимые статические настройки, устанавливает принадлежащую dotm интеграцию `.chezmoiignore`, публикует начальную политику и проверяет обычное обнаружение. Совпадающий существующий checkout проверяется локально, без fetch/fast-forward. Посторонние незакоммиченные изменения источника и нативные правила игнорирования сохраняются; небезопасная, неоднозначная, частично размеченная или изменённая пользователем интеграция требует исправления вручную. Совместимые настройки chezmoi сохраняются; минимальный статический TOML создаётся лишь при отсутствии выбранной обычной конфигурации.

Init не устанавливает выбранные приложения, не запускает их хуки, не применяет файлы назначения, не коммитит изменения источника и не переключает origin молча. Получение отсутствующего checkout и явная замена следуют строгим правилам безопасности; резервные копии при замене и все завершённые эффекты отражаются в отчёте. Поздний сбой может последовать за частичными изменениями: проверьте перечисленные файлы, пакетные эффекты, резервные копии и публикацию политики, не считая операцию транзакцией. Просмотрите diff и самостоятельно закоммитьте изменения checkout. Успешный повтор не создаёт ненужных изменений. См. [сценарий команды](usage.md#инициализация-dotm) и [интеграцию chezmoi](chezmoi.md).

## Сначала просмотр, затем развёртывание

```sh
./dotm configs
./dotm apps
./dotm show
./dotm status
# Меняет пакеты, может запускать хуки и применять конфигурационные файлы:
./dotm install
./dotm status
```

`configs`, `apps` и `show` не требуют Nix. `status` читает нативный профиль. Первая установка фиксирует ревизию `github:NixOS/nixpkgs/nixos-unstable`; следующие установки при исправном состоянии используют её повторно. Для продвижения ревизии нужен явный `update`. Перед развёртыванием своего каталога изучите [использование](usage.md) и [границы восстановления](troubleshooting.md).
