# Справочник настроек

[Документация](README.md) · [English](../en/configuration.md)

## Общий каталог: catalog.toml

Приложения задаются именованными TOML-таблицами, не записями `[[apps]]`:

```toml
[git]
nix = ["git"]
configs = ["$XDG_CONFIG_HOME/git"]

[search]
dependencies = ["git"]
nix = ["ripgrep", "fd"]

[json]
nix = ["yq-go", { attr = "jq", outputs = ["bin", "man"] }]

[shell]
dependencies = ["search"]
nix = ["zsh"]
configs = ["~/.zshrc"]
unmanaged = ["$XDG_STATE_HOME/zsh", "$XDG_CACHE_HOME/zsh"]
pre_hook = "hooks/check-home"
pre_cfg_hook = "hooks/prepare-shell"
post_cfg_hook = "hooks/check-shell"

[ssh-settings]
configs = ["~/.ssh/config"]

[workspace]
dependencies = ["shell", "json", "ssh-settings"]
```

| Поле | Значение |
| --- | --- |
| `nix` | Необязательные дескрипторы пакетов; отсутствие/пустой список означает отсутствие собственных пакетов |
| `dependencies` | ID других приложений, транзитивно обрабатываемых до потребителей |
| `configs` | Принадлежащие приложению пути назначения, абсолютные после раскрытия; файлы или каталоги |
| `unmanaged` | Известные данные приложения, исключаемые из синхронизации/инвентаризации при его выборе |
| `pre_hook` | Исполняемый повторяемый хук перед пакетной частью |
| `pre_cfg_hook` | Исполняемый повторяемый хук перед получением/проверкой/применением конфигурации |
| `post_cfg_hook` | Исполняемый повторяемый хук после успешной конфигурации с учётом зависимостей |

Строка пакета выбирает стандартные outputs, таблица — явные. Формы можно смешивать. Атрибуты относятся к `nixpkgs.legacyPackages.${system}`. Одинаковые дескрипторы обрабатываются один раз, приложения могут делить пакеты. Логические зависимости — желаемые спутники, а не технические зависимости Nix. Неизвестные зависимости и циклы — ошибки. Агрегаторы и конфигурационные приложения без пакетов допустимы; `post_hook` и старый формат `[[apps]]`/`id`/`packages` не поддерживаются.

### Пути и владение

Пути конфигураций/данных раскрывают HOME, начальные `~`/`~/` и переменные окружения без оболочки. XDG config/data/state/cache homes по умолчанию соответствуют стандартным каталогам HOME. `${VAR:-fallback}` поддерживает значения по умолчанию, включая вложенные выражения; неизвестная переменная без default — ошибка. `configs`/`unmanaged` должны стать абсолютными. Пути нормализуются и сравниваются лексически, без требования существования и перехода по символьным ссылкам.

Во **всём каталоге** разные приложения не могут владеть равными/вложенными `configs`, а `configs` любого приложения не могут пересекаться с любыми `unmanaged`. Избыточность внутри списка и пересечения unmanaged дают предупреждения. Цель-каталог выбирает управляемых потомков из исходников, но не объявляет любые неизвестные локальные файлы синхронизируемыми. Конфликты локальных исключений с владением выявляются files lint.

## Общие наборы: configurations.toml

```toml
[[configurations]]
name = "laptop"
apps = ["workspace"]
backend = "chezmoi"
repository = "https://example.invalid/my-dotfiles.git"

[[configurations]]
name = "packages-only"
apps = ["json"]

[[configurations]]
name = "empty"
apps = []
```

Замените вымышленный URL настоящим адресом Git. Указывайте `backend` и `repository` непосредственно в каждой записи `[[configurations]]` рядом с `name` и `apps`; прежний вложенный формат `[configurations.configs]` отвергается. Для каждого набора, чьё замыкание зависимостей содержит конфигурационные цели, обязательна пара `backend = "chezmoi"` и непустой `repository`. Пакетные/пустые наборы могут опустить оба поля, но любое непустое значение источника требует корректную пару. Настройки источника принадлежат именованной конфигурации, а не локальному выбору. Все наборы используют одну локальную рабочую копию: другой URL может потребовать защищённой замены источника. Пустой набор не означает удаление или применение без ограничения целей.

## Локальный выбор: config.toml

Путь: `${XDG_CONFIG_HOME:-$HOME/.config}/dotm/config.toml`.

```toml
configuration = "laptop"
```

Файл выбирает существующее имя. dotm не определяет машину и не создаёт выбор автоматически. Общие данные по умолчанию находятся в соседнем `data/`; относительный `--data-dir` считается от текущего каталога и не переносит локальные настройки.

## Локальные исключения: files.toml

Необязательный файл рядом с `config.toml`:

```toml
[unmanaged]
"$XDG_CONFIG_HOME" = ["browser-local", "tool with spaces"]
"$XDG_CACHE_HOME" = ["manual-downloads"]
"~" = ["Downloads", "scratch"]
```

Ключи-родители раскрываются в абсолютные пути. Значения — буквальные имена непосредственных детей, не шаблоны и не раскрываемые пути: wildcard-символы и `$VAR` остаются буквальными. Пустые имена, `.`/`..`, слеши и NUL недопустимы. Признаются известными только эти дети, не весь родитель. Отсутствующий файл означает отсутствие локальных исключений. Признание данных известными не создаёт/удаляет их и не означает, что их безопасно выбросить. Различие фильтрации по выбору и классификации инвентаризации описано в [работе с файлами](chezmoi.md).

## Хуки

Значение хука — путь к одному исполняемому файлу, не командная строка/массив аргументов. Относительные пути и рабочий каталог отсчитываются от каталога `catalog.toml`. Поддерживаются абсолютные/home-relative пути, переменные и вложенные defaults. Подстановки команд, разбиения слов, glob и вычисления оболочкой нет.

Пример скрипта: самостоятельно создайте `hooks/check-home` и выставьте исполняемый бит:

```bash
#!/usr/bin/env bash
set -eu
test -d "$HOME"
```

Хуки запускаются напрямую, наследуют окружение с `bin` управляемого профиля первым в PATH, получают закрытый stdin и выводят оба потока в stderr dotm. dotm не меняет права. Пакетный pre-хук не может рассчитывать на ещё не установленные пакеты.

Порядок полного цикла: **пакетные pre-хуки → пакеты → готовые pre-конфигурационные хуки → источник/lint/политика/apply → post-конфигурационные хуки**. Зависимости идут до потребителей, приложение выполняется один раз на стадию. Pre-хуки установки охватывают весь желаемый набор даже без новых пакетов; пакетные хуки update — область пакетных свидетельств и зависимостей. Конфигурационная часть охватывает весь готовый желаемый набор. `update cfg` пропускает пакетные хуки/операции. Просмотр и удаление не запускают хуки.

Ошибки пакетного pre-хука/пакетов не допускают конфигурационную часть. Ошибка pre-конфигурационного хука блокирует приложение и конфигурационные стадии потребителей, независимая работа продолжается. Конфликты допускают безопасные изменения файлов/конфигураций потребителей, но блокируют post-хуки затронутого приложения/потребителей. Ошибка post-хука блокирует post-хуки потребителей. Хуки повторяются без базы завершения. Пишите доверенные хуки устойчивыми к повторам/прерыванию: откат профиля не отменяет их изменений пользовательских данных.
