## Безопасный просмотр: без Nix и изменения профиля

Сначала соберите CLI по [инструкции установки](installation.md). Выполните блок из корня репозитория в Bash. Он создаёт временный локальный выбор, не перезаписывая настоящий. Trap удаляет только этот временный каталог. Бэкенды, загрузки, хуки и применение конфигураций не запускаются.

```bash
(
  set -eu
  demo=$(mktemp -d)
  trap 'rm -rf -- "$demo"' EXIT
  export XDG_CONFIG_HOME="$demo/config"
  mkdir -p "$XDG_CONFIG_HOME/dotm"
  printf 'configuration = "laptop"\n' > "$XDG_CONFIG_HOME/dotm/config.toml"

  ./dotm --data-dir examples configs
  ./dotm --data-dir examples apps
  ./dotm --data-dir examples show

  printf 'configuration = "minimal"\n' > "$XDG_CONFIG_HOME/dotm/config.toml"
  ./dotm --data-dir examples show
)
```

[Комплектный каталог](../../examples/catalog.toml) и [наборы](../../examples/configurations.toml) содержат только пакеты:

| Выбор | Прямые приложения | Порядок после раскрытия зависимостей |
| --- | --- | --- |
| `laptop` | `terminal`, `git`, `json` | `zoxide`, `git`, `zsh`, `search`, `terminal`, `json` |
| `minimal` | `git`, `search` | `git`, `search` |

Пакеты: zsh, zoxide, git, ripgrep, fd, eza и jq; для jq явно выбраны `bin` и `man`. `show` выводит уникальные дескрипторы без вычисления nixpkgs. Это демонстрация манифестов, не проверка готовности хоста.

## Реальный пакетный сценарий

Следующие команды **не входят в безопасное демо**. Они используют реальные локальные настройки и стандартный XDG-профиль Nix. Завершите [подготовку хоста](installation.md), осознанно создайте локальный выбор и просмотрите состояние до изменений:

```sh
./dotm --data-dir examples show
./dotm --data-dir examples status
./dotm --data-dir examples install
./dotm --data-dir examples update
```

Для смены набора отредактируйте выбор на `minimal`, просмотрите статус, затем рассмотрите предложения `remove-extras`. Выберите `laptop` и выполните install для восстановления недостающих приложений с текущим lock. Очистка/GC — отдельная явная операция. Изменение только XDG_CONFIG_HOME не изолирует пакеты: нативный профиль зависит от XDG_STATE_HOME/HOME.

## Полный статический showcase настроек

[examples/showcase](../../examples/showcase/README.md) показывает агрегаторы, приложения только с конфигурациями, общие дескрипторы, явные outputs, владение файлами/каталогами, unmanaged-данные, все три хука, несколько именованных наборов и локальные настройки.

Это **не запускаемый набор**: URL с `.invalid` вымышлены; реализации хуков и содержимое исходников отсутствуют. Дерево `local/` представляет файлы в config home условного пользователя, а не автоматически обнаруживаемые соседние с каталогом файлы. Замените URL, реализуйте хуки и подготовьте пути перед использованием в реальной настройке. Смена профиля сама не удаляет пакеты или файлы назначения.

## Пример интеграции файловой политики

`dotm init` устанавливает собственную корневую интеграцию для настроенного источника. При исправлении небезопасной или неоднозначной интеграции используйте [examples/chezmoi-policy](../../examples/chezmoi-policy/) как справочник и сохраняйте нативные правила; не перезаписывайте живую конфигурацию незаполненными примерами. См. [руководство интеграции](chezmoi.md). Политика всегда обнаруживается по `${XDG_STATE_HOME:-$HOME/.local/state}/dotm/chezmoi-policy.json`; настройка `policyFile` и хешированный путь не нужны.

## Воспроизведение проверок бэкендов

Прежние изолированные сценарии с реальными бэкендами и их границы окружения/защиты описаны отдельно:

- [Пакетная приёмка](../../.agent/acceptance.md): Arch и одноразовый Ubuntu, обычный пользователь многопользовательского демона, откат и явная GC.
- [Приёмка конфигураций/файлов](../../.agent/configuration-acceptance.md): прежние проверки жизненного цикла и [составная приёмка init/doctor](../../.agent/configuration-acceptance.md#composed-init-and-doctor-acceptance) с изолированными HOME/нестандартными XDG/данными, реальным получением chezmoi, миграцией старой интеграции, жизненным циклом и диагностикой частичного сбоя на Arch.

Это записи проверок для разработчиков, не команды для повторения на живом профиле. См. [границы покрытия](troubleshooting.md).
