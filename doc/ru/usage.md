# Команды и рабочие сценарии

[Документация](README.md) · [English](../en/usage.md)

Примеры используют стандартный каталог данных. Для другого общего каталога добавьте `--data-dir /path/to/data`. Длинные параметры начинаются с `--` и могут стоять до или после команды. Синтаксис доступен через `./dotm --help` и `./dotm <command> --help`.

## Справочник команд

| Команда | Действие |
| --- | --- |
| `configs` | Список конфигураций и прямых выборок; локальный выбор и Nix не нужны |
| `apps` | Каталог приложений, зависимости, пакеты, цели и пути хуков; локальный выбор и Nix не нужны |
| `show` | Локальный выбор, приложения после раскрытия зависимостей, уникальные пакеты и владельцы целей; Nix не нужен |
| `status` | Просмотр пакетов и готовности без изменений; не проверяет содержимое файлов |
| `install` | Хуки, установка недостающих желаемых пакетов, синхронизация готовых конфигураций |
| `update` | Продвижение источника, обновление установленных желаемых приложений и полного набора их логических зависимостей; синхронизация всех готовых желаемых конфигураций |
| `update cfg` | Синхронизация готовых конфигураций без пакетных операций и пакетных pre-хуков |
| `cfg lint [--source /absolute/checkout]` | Пассивная локальная проверка исходников/настроек; манифесты, выбор, Nix и бинарный файл chezmoi не нужны |
| `files lint` | Проверка деклараций, действующих нативных правил и подключения опубликованной политики |
| `files refresh [--update-source]` | Подготовка, проверка и публикация политики; получение/обновление исходников — только с явным флагом |
| `files status` | Локальное обновление политики и инвентаризация изменений/неклассифицированных файлов; без загрузки исходников |
| `remove-extras [--yes]` | Удаление явно одобренного лишнего с защитой желаемых дескрипторов |
| `clean [--keep N] [--gc] [--dry-run] [--yes]` | Отдельная очистка истории и необязательная сборка мусора общего хранилища; манифесты и выбор не нужны |

Команды `files` вычисляют доверенные шаблоны, но не применяют конфигурации, не запускают хуки приложений и не проверяют Nix. См. [chezmoi и файлы](chezmoi.md).

## Просмотр и установка

```sh
./dotm show
./dotm status
./dotm install
./dotm status
```

Статус различает установленные, частичные, отсутствующие и беспакетные приложения, явные нативные записи и лишнее. Готовность конфигурации учитывает полное замыкание зависимостей; это не историческая отметка об установке и не доказательство синхронизации файлов.

При исправном источнике установка добавляет только недостающие дескрипторы, включая части многопакетных приложений. Установленное, лишнее и lock источника сохраняются. Повторная установка уже полного набора всё равно выполняет настроенные хуки/конфигурационные стадии. Неоднозначные желаемые записи приводят к ошибке, а не автоматическому исправлению.

## Обновление

```sh
./dotm update
# Повторить только конфигурационную часть:
./dotm update cfg
```

Обновление продвигает локальную фиксацию `nixos-unstable`. Область определяется активными пакетными записями: частичные приложения дополняются, включаются все текущие компоненты и транзитивные логические спутники, в том числе недавно добавленные. Общий активный дескриптор может свидетельствовать о частичной установке нескольких приложений. Установленный спутник не выбирает отсутствующего родителя; полностью отсутствующие независимые приложения остаются для `install`. Одни неактивные записи не запускают обновление. Лишнее сохраняет версии. Без установленных желаемых приложений пакетная часть ничего не делает, но готовые конфигурации всё равно обрабатываются.

Изменения lock и путей пакетов в store выводятся отдельно: новая ревизия источника не обязана менять версии пакетов. Ошибки пакетной части/источника запускают восстановление; поздние конфигурационные ошибки сохраняют успешные пакетные изменения. См. [восстановление](troubleshooting.md).

## Смена конфигурации и удаление лишнего

Измените `configuration` в локальном `config.toml`, проверьте `show`/`status`, затем выполните `install`. Сам выбор не удаляет пакеты и файлы назначения. Для лишних пакетов:

```sh
./dotm remove-extras
# Явно одобрить все удаления без вопросов:
./dotm remove-extras --yes
```

Каждое лишнее приложение подтверждается отдельно. Желаемые/общие компоненты защищены; общий компонент лишних приложений удаляется только при одобрении всех использующих его приложений. Неизвестные/внешние и неактивные записи желаемых дескрипторов рассматриваются отдельно. `y`/`yes` — согласие, Enter или `n`/`no` — отказ, `q`/`quit` — отмена. EOF/ошибка ввода отменяет весь собранный план; перенаправленный ввод должен содержать полную строку для каждого вопроса. Перед одним нативным пакетом удалений состояние проверяется повторно.

Удаление не меняет lock, не сокращает историю, не удаляет объекты store и не отменяет действия над пользовательскими данными. Нативная ошибка может оставить частичный результат; выводится фактическое состояние без автоматического отката/повтора.

## История и место на диске

```sh
./dotm clean --dry-run
./dotm clean
./dotm clean --keep 1 --gc
```

По умолчанию остаются активное поколение и два **других** с наибольшими номерами. `--keep N` меняет число дополнительных поколений; `--keep 0` удаляет все альтернативы отката. После отката альтернативы могут быть новее активного поколения. Очищается история только стандартного XDG-профиля.

Без `--gc` удаление корней истории может не освободить место пакетов. **`--gc` разрешает сборку мусора во всём общем store, включая посторонние сборки и кеши без корней.** Активный/сохранённые профили и другие GC roots защищают свои объекты. `--dry-run --gc` показывает мусор при текущих корнях, а не дополнительный мусор, который появится после удаления истории.

Ответы подтверждения такие же, как для удаления; `--yes` обходит вопрос, а изменение истории отменяет одобренный план. Ошибки не восстанавливают уже удалённую историю автоматически. Нативный откат к сохранённому поколению описан в [устранении проблем](troubleshooting.md).

## Совмещение операций

```sh
./dotm -iur
./dotm -iur --yes
```

`-i`/`--install`, `-u`/`--update`, `-r`/`--remove-extras` допускают группировку или отдельные флаги. Порядок всегда **update → install → remove-extras**, каждая выбранная операция выполняется один раз независимо от порядка/повторов флагов. Не смешивайте их с подкомандой. `--yes` требует удаления или отдельного `clean` и никогда не подтверждает замену исходников. Очистка не включается.

Манифесты/выбор читаются один раз, но каждая операция заново проверяет пакеты. Установка и обновление сохраняют отдельные циклы хуков/конфигураций. Конфигурационные ошибки допускают следующие операции; ошибки пакетов/pre-хуков/внутренние ошибки останавливают последовательность. Сохраняется максимальный код ошибки; предыдущие изменения не отменяются. Другой порядок задавайте отдельными командами через `&&`.

## Параллельность и вывод

На один пользовательский XDG state-каталог разрешена одна изменяющая операция: `install`, `update`, `update cfg`, `files refresh`, `files status`, `remove-extras` и `clean` без dry-run сразу завершаются ошибкой при занятой блокировке. Комбинация держит её во время вопросов и хуков. Вложенная изменяющая команда из хука не ждёт, а завершается ошибкой. Чтение и dry-run очистки доступны, но не дают атомарного снимка.

Приватные файлы Linux flock находятся в `/tmp/dotm-<uid>/`; не удаляйте их во время возможной работы процессов. Нативные дочерние процессы update/add/recovery сохраняют владение после гибели dotm; хуки — нет, поэтому остановите оставшиеся хуки перед повтором. Прямые изменения Nix/Git/chezmoi не координируются, как и разные state-каталоги с одним источником.

stdout содержит просмотр и фактические результаты операций; stderr — диагностику стадий и вывод нативных команд/хуков. Ненулевой код возможен после успешных изменений пакетов или файлов. См. [коды и повтор](troubleshooting.md).
